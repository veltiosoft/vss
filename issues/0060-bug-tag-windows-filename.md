# bug: タグページの出力ファイル名を OS 非依存にサニタイズする

- Polished: {YYYY-MM-DD}

## 目的

タグ名は URL ではパーセントエンコードされるが、出力ファイル名には生のタグ名が使われる。Windows で無効な `?`、`*`、`<`、`>`、`|`、`"` や末尾のドット・空白を含むタグでビルドが失敗するため、出力ファイル名をサニタイズする。

## 現状

確認対象: `main` の `db75abf`（v0.21.0）。

- `src/subcommand_build.rs` の `is_safe_tag_name` は `..`、`/`、`\`、`:`、制御文字を拒否する。
- `tag_url` は URL セグメントをパーセントエンコードする。
- `tag_output_path` は `config.build.tags.url_pattern.replace("{tag}", tag)` をそのまま `Path::new(&config.dist).join(...)` に使い、生のタグ名をファイル名にする。
- Windows のファイル名で無効な `?`、`*`、`<`、`>`、`|`、`"`、末尾のドット・空白は拒否されない。`fs::create_dir_all` / `fs::write` が失敗し、ビルド全体が止まる。
- macOS / Linux では同名のファイルを作成できるため、クロスプラットフォームで挙動が異なる。

## 設計方針

- URL 用のタグ名（パーセントエンコード）とファイル名用のタグ名を分離する。
- ファイル名用には Windows の予約名（`CON`, `PRN`, `AUX`, `NUL`, `COM1` など）と無効文字、末尾のドット・空白を安全な表現へ置換する。
- 置換後の名前が衝突しないよう、必要ならハッシュや連番を付ける。ただし既存の URL との対応を壊さない。
- 不正なタグ名を拒否するか、安全なファイル名へ変換するかを決め、テストで確認する。

- [ ] 生成されたタグページが、対応するタグ URL から到達できる。
- [ ] 既存の安全なタグ（英数字、日本語、`C++`、`a b`）の URL と出力先が変わらない。
