# Markdown の探索範囲を明示的に限定する方法を検討する

- ラベル: `enhancement`, `migration`
- 元 issue: なし（ローカル起票）

## 背景と課題

vss はサイトルートから Markdown を再帰探索する。
移行元リポジトリには公開原稿以外に `archive/` や `docs/` があるため、そのままサイトルートにすると意図しないページが生成されうる。
現行の `build.ignore_files` はパスに含まれる文字列で除外する。
隠しディレクトリや専用サイトディレクトリも回避策だが、既存の原稿配置を維持しにくい。

## 検討事項

- 許可するコンテンツルートまたは対象パスを明示する設定と既存動作の互換性。
- `partials/`、静的ファイル、テンプレート、隠しパスとシンボリックリンクの扱い。
- 出力パスの起点と複数ルートの衝突、serve の監視範囲。
- 誤設定時に予期しないファイルが公開されないエラーや診断。
