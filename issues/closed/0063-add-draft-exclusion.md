# front matter による下書きの公開除外を検討する

- Created: 2026-10-28
- 状態: 解決済み
- 優先度: P1
- ラベル: `enhancement`, `migration`
- 元 issue: なし（ローカル起票）

## 背景と課題

移行元サイトでは `draft: true` の記事を個別ページ、一覧、タグ、フィードから除外している。
vss の現行スキルではこの front matter を公開除外条件として扱わず、隠しディレクトリや除外設定の利用を案内している。
原稿をそのまま移すと下書きが生成されるおそれがある。

## 検討事項

- 下書きのフィールド、既定値、不正な値の扱いと、既存サイトへの影響。
- 個別ページに加え、タグページや将来の一覧とフィードにも同じ除外条件を適用する方法。
- `vss serve` で公開から下書きに変更した際の古い出力の削除。
- 下書きのプレビュー機能を設ける場合の明示的な操作と安全な既定値。

## 完了条件

- [x] 下書きの公開とプレビューの仕様を定め、ドキュメントに記載する。
- [x] 全体ビルドと増分ビルドで公開対象への混入や古い出力の残存を防ぐテストを追加する。

## 解決方法

- `draft` は省略時に `false` とし、`true` の Markdown を個別ページ、記事一覧、タグ一覧、タグページの投稿から除外した。Markdown 部品にも適用する。
- 真偽値以外の文字列、数値、`null` はビルドエラーにする。下書きプレビューは提供しない。
- 公開ページのメタデータを全体ビルドと増分ビルドで共有し、公開から下書きへの変更時は全体を再生成して古い出力を除く。
- 静的ファイルのコピーは対象外とし、非公開原稿を `static/` に置かないこと、重複する静的 HTML は残ることを文書化した。
- 仕様と利用例は `site/docs/posts.md` と `skills/vss/SKILL.md`、回帰テストは `src/subcommand_build/tests/publication.rs` に記載した。
- `cargo test --locked` と `cargo clippy --locked --all-targets -- -D warnings` を通過した。移行元の記事 39 件のコピーでも公開 38 件と下書き 1 件の除外を確認し、`serve` 経由で公開から下書きへの変更と再公開を検証した。
